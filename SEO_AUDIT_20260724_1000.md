## Score SEO Global : 6/10

**Justification :** Le site dispose de bonnes bases SEO (metadata sur le layout principal, balises sémantiques HTML5, images next/image, lang="fr" correct, structure URL propre), mais il manquait de deux éléments fondamentaux pour l'indexation — le sitemap et les robots.txt — et plusieurs pages importantes n'ont pas de balises `<title>` ni de `<description>` propres. La structure de contenu est de qualité, le code est moderne (Next.js App Router), mais l'absence de balises Open Graph images et les métadonnées manquantes sur certaines pages tirent le score vers le bas.

---

## Points Forts

- `lang="fr"` correctement défini sur la balise `<html>`
- `translate="no"` présent pour éviter la traduction automatique (contenu gabonais spécifique)
- `metadataBase` correctement configuré sur `https://www.odillon.fr`
- Utilisation de `next/image` pour toutes les images (optimisation automatique, lazy-loading, formats modernes)
- Titres et descriptions définis dans le layout global (fallback efficace)
- Balises `<h1>` présentes sur toutes les pages visitées
- Open Graph de base configuré (type, locale fr_FR, url, siteName)
- Balises `robots: { index: true, follow: true }` dans le layout
- Structure d'URL sémantique et lisible (`/offres/gouvernance`, `/blog/[slug]`)
- `generateMetadata()` dynamique pour les articles de blog et les sous-services
- Pages légales présentes (`/mentions-legales`, `/politique-confidentialite`)
- Données structurées potentielles via les sections de contenu bien organisées

## Problèmes Critiques (P1)

### P1-1 — Sitemap XML absent
**Fichier :** `app/sitemap.ts` (inexistant avant cet audit)  
**Impact :** Les moteurs de recherche découvrent le site par crawl seul, sans carte des routes. Les nouvelles pages peuvent mettre des semaines à être indexées.  
**Action effectuée :** Création de `app/sitemap.ts` avec toutes les routes statiques et les articles dynamiques récupérés depuis Supabase.

### P1-2 — Fichier robots.txt absent
**Fichier :** `app/robots.ts` (inexistant avant cet audit)  
**Impact :** Sans ce fichier, les robots d'indexation accèdent à toutes les routes y compris les routes admin (`/admin/*`), les routes API, et le dashboard.  
**Action effectuée :** Création de `app/robots.ts` avec les règles appropriées : blocage de `/admin/`, `/api/`, `/dashboard/`, `/auth/`, `/backgrounds-demo/`, et les routes de satisfaction/inscription des formations. Blocage des robots IA (GPTBot, Google-Extended, CCBot, anthropic-ai).

### P1-3 — Metadata manquante sur la page `/offres`
**Fichier :** `app/offres/page.tsx` ligne 1 (`"use client"`)  
**Impact :** La page principale des offres est un composant client — impossible d'exporter `metadata` depuis un Client Component en Next.js App Router. Google voit uniquement le titre générique du layout.  
**Recommandation :** Créer un fichier `app/offres/layout.tsx` (Server Component) pour injecter le metadata, ou convertir le composant en Server Component avec chargement dynamique des parties interactives.

### P1-4 — Metadata manquante sur la page `/contact`
**Fichier :** `app/contact/page.tsx`  
**Impact :** Pas de `<title>` ni `<description>` spécifiques. Google utilise le titre générique du layout, ce qui nuit au taux de clic depuis les pages de résultats pour des recherches du type "contact cabinet conseil Gabon".

### P1-5 — Metadata manquante sur la page `/mentions-legales`
**Fichier :** `app/mentions-legales/page.tsx`  
**Impact :** Page légale sans balise `<title>` propre. Bien que la priorité SEO soit faible pour cette page, l'absence de metadata peut créer un signal négatif de qualité.

### P1-6 — Metadata manquante sur la page `/politique-confidentialite`
**Fichier :** `app/politique-confidentialite/page.tsx`  
**Impact :** Même problème que pour les mentions légales.

### P1-7 — Page `/phototheque` entièrement côté client sans metadata
**Fichier :** `app/phototheque/page.tsx` ligne 1 (`"use client"`)  
**Impact :** Aucun metadata SEO possible. La galerie photo n'est pas indexable car le contenu est chargé dynamiquement côté client après la navigation.

## Recommandations (P2)

### P2-1 — Images Open Graph absentes
**Localisation :** `app/layout.tsx` lignes 21-28  
Le bloc `openGraph` ne définit pas de `images`. Chaque partage sur les réseaux sociaux affichera un aperçu vide ou le favicon.  
**Recommandation :** Créer une image OG par défaut (1200×630px) et l'ajouter dans le layout :
```typescript
openGraph: {
  images: [{ url: '/og-image.jpg', width: 1200, height: 630, alt: 'Odillon - Cabinet de Conseil au Gabon' }],
}
```

### P2-2 — Pas d'image pour la Twitter Card
**Localisation :** `app/layout.tsx` lignes 29-33  
La Twitter Card est configurée en `summary_large_image` mais sans image, ce qui la dégrade automatiquement en simple `summary`.  
**Recommandation :** Ajouter `images: ['/og-image.jpg']` dans le bloc `twitter`.

### P2-3 — Canonical URLs non définis explicitement
Les pages n'exportent pas de `alternates.canonical`, ce qui peut causer des problèmes de contenu dupliqué entre `odillon.fr` et `www.odillon.fr`.  
**Recommandation :** Ajouter dans le layout global :
```typescript
alternates: {
  canonical: 'https://www.odillon.fr',
}
```
Et déclarer le canonical sur chaque page importante.

### P2-4 — Description de la page communication trop générique
**Fichier :** `app/offres/communication/page.tsx` ligne 11  
`"La communication est l'ensemble des interactions avec autrui qui transmettent une quelconque information."` — Cette description ressemble à une définition de dictionnaire plutôt qu'à une valeur métier. Elle ne contient pas de mots-clés différenciants.  
**Recommandation :** Remplacer par une description orientée bénéfices et géolocalisation.

### P2-5 — Absence de données structurées (JSON-LD)
Le site n'implémente pas de Schema.org. Pour un cabinet de conseil, les types suivants seraient bénéfiques :
- `Organization` sur la page d'accueil (adresse, téléphone, email)
- `LocalBusiness` avec la géolocalisation Libreville, Gabon
- `Article` sur les pages de blog
- `BreadcrumbList` sur les pages offres/sous-services

### P2-6 — Redirections www/non-www non vérifiables côté code
**Fichier :** `proxy.ts`  
S'assurer que les requêtes sur `odillon.fr` (sans www) sont redirigées en 301 vers `www.odillon.fr` pour éviter la duplication de contenu.

## Opportunités (P3)

### P3-1 — Blog sans catégories dans les URLs
Les articles de blog utilisent uniquement `/blog/[slug]`. L'ajout d'une catégorie dans l'URL (`/blog/gouvernance/[slug]`) améliorerait la structure de siloing thématique.

### P3-2 — Calendrier des formations sans données enrichies
La page `/calendrier-formations` affiche les formations mais sans balises `Event` de Schema.org, ce qui empêche l'affichage enrichi dans les résultats Google (dates, lieu, prix).

### P3-3 — Absence de page 404 personnalisée
Aucune page `app/not-found.tsx` n'est visible dans la structure. Une page 404 avec navigation vers les sections principales améliore l'expérience utilisateur et retient les visiteurs.

### P3-4 — Métadonnées manquantes sur les pages légales
Ajouter des exports `metadata` sur `/mentions-legales` et `/politique-confidentialite` avec des instructions `noindex` pour éviter que ces pages ne consomment du "crawl budget" :
```typescript
export const metadata = {
  title: "Mentions Légales | Odillon",
  robots: { index: false, follow: false }
}
```

### P3-5 — Favicon non optimisé pour tous les formats
Le favicon utilise un `.webp` pour toutes les tailles (icon, shortcut, apple). Envisager d'utiliser un `.ico` pour les navigateurs anciens et un `.svg` pour les navigateurs modernes.

### P3-6 — Maillage interne à renforcer
La photothèque et le calendrier des formations sont peu liés depuis les autres pages. Ajouter des liens contextuels vers ces pages depuis les sections services et blog améliorerait la distribution du "link equity".
