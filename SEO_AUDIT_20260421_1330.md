## Problèmes identifiés et corrections appliquées

### P1 — `unoptimized` désactivait l'optimisation d'images (CRITIQUE) ✅ Corrigé

**Fichiers concernés :**
- `components/sections/trusted-by-home.tsx` (ligne 42 avant correction)
- `components/ui/icon-3d.tsx` (ligne 44 avant correction)

**Problème :** Le prop `unoptimized` désactive entièrement le pipeline d'optimisation Next.js, ce qui empêche :
- La conversion automatique en formats AVIF et WebP
- Le lazy loading automatique
- La génération de srcset responsive

**Correction :** Suppression de `unoptimized`, ajout de `sizes` et `loading="lazy"`. Le mécanisme `onError` de fallback format restait parfaitement fonctionnel sans ce prop. L'alt a été enrichi avec le nom complet de l'entreprise pour le SEO (`Logo CDC — Caisse des Dépôts et Consignations`).

---

### P2 — Balise `<img>` HTML natif dans l'admin (IMPORTANT) ✅ Corrigé

**Fichier :** `app/admin/photos/page.tsx` (ligne 854 avant correction)

**Problème :** Une seule balise `<img>` native subsistait dans le panneau d'administration pour afficher les photos Supabase. Même si cette page n'est pas indexée par les moteurs de recherche, l'utilisation de `<Image>` de next/image garantit des optimisations automatiques et une cohérence du codebase.

**Correction :** Migration vers `<Image fill sizes="..." loading="lazy">` dans son conteneur `aspect-video`.

---

### P3 — `next.config.js` : formats AVIF/WebP et remotePatterns (CRITIQUE) ✅ Corrigé

**Fichier :** `next.config.js`

**Problèmes avant correction :**
1. `hostname: '**'` — acceptait TOUTES les URLs HTTPS externes (surface d'attaque trop large, pas de contrôle sur les sources d'images)
2. Absence de `formats: ['image/avif', 'image/webp']` — Next.js ne servait pas les formats modernes par défaut

**Correction :**
```js
images: {
  formats: ['image/avif', 'image/webp'],
  remotePatterns: [
    { protocol: 'https', hostname: 'images.unsplash.com' },
    { protocol: 'https', hostname: 'xqkaraihiqqfcasmduuh.supabase.co',
      pathname: '/storage/v1/object/public/**' },
  ],
}
```

Les deux seules sources d'images externes réellement utilisées ont été identifiées dans le code : Unsplash (photos de fond par défaut dans `lib/photo-themes.ts`) et Supabase Storage (photos uploadées via l'admin).

### P4 — Alt des logos enrichis pour le SEO (IMPORTANT) ✅ Corrigé

**Fichiers concernés :**
- `components/layout/header.tsx` — `alt="Odillon — Cabinet de conseil en ingénierie d'entreprises au Gabon"`
- `components/layout/header-pro.tsx` — même texte avec `sizes="(max-width: 768px) 240px, 350px"`
- `components/layout/footer.tsx` — même texte enrichi + `loading="lazy"` + `sizes`
- `components/sections/trusted-by-home.tsx` — alt enrichi avec nom complet des entreprises

**Problème :** Les logos du header avaient `alt="Odillon"` ou `alt="Odillon - Ingénierie d'Entreprises"` sans préciser le pays, ce qui pénalise la pertinence géographique. La prop `sizes` était absente sur tous les logos, empêchant le navigateur de choisir la taille optimale.

### P5 — Imports dynamiques pour les sections sous le fold (IMPORTANT) ✅ Corrigé

**Fichier :** `app/page.tsx`

**Problème :** Les cinq sections de la homepage (`TrustedByHome`, `ServicesHome`, `ExpertiseHome`, `AboutHome`, `ContactHome`) étaient importées statiquement, ce qui les incluait dans le bundle JavaScript initial. Ces sections utilisent Framer Motion et des composants lourds — elles n'ont pas besoin d'être présentes dans le bundle initial puisqu'elles sont sous le fold.

**Correction :** Remplacement des imports statiques par `next/dynamic` pour les 5 sections sous le fold. `Hero` reste en import statique car il est visible immédiatement (au-dessus du fold, impact direct sur le LCP).

```typescript
const TrustedByHome = dynamic(() => import("@/components/sections/trusted-by-home").then(m => ({ default: m.TrustedByHome })))
// ... idem pour ServicesHome, ExpertiseHome, AboutHome, ContactHome
```

---

### P6 — Polices : `preload` explicite et fallback Baskvill (AMÉLIORATION) ✅ Corrigé

**Fichiers :** `app/fonts.ts`, `app/layout.tsx`

**Baskvill (`app/fonts.ts`) :**
- Ajout de `preload: true` (explicite) pour que Next.js génère le `<link rel="preload">` dans le `<head>`
- Ajout de `fallback: ['Georgia', 'serif']` pour limiter le CLS (Cumulative Layout Shift) pendant le chargement de la police custom

**Inter (`app/layout.tsx`) :**
- Ajout de `display: "swap"` (était absent, Next.js le fait par défaut mais mieux d'être explicite)
- Ajout de `variable: "--font-inter"` pour la cohérence avec le pattern Baskvill

---

### P7 — JSON-LD Organization + LocalBusiness (SEO) ✅ Corrigé

**Fichier :** `app/layout.tsx`

**Problème identifié lors de l'audit précédent (P2-1) :** Absence de données structurées JSON-LD — le site n'était pas éligible aux rich snippets Google (Knowledge Panel, LocalBusiness).

**Correction :** Ajout d'un script JSON-LD `Organization` + `LocalBusiness` dans le `<head>` du layout racine :
- Nom, description, URL, logo
- Adresse postale (Libreville, Gabon)
- Téléphone et email de contact
- Domaines d'expertise (`knowsAbout`)

## Recommandations restantes (non traitées dans cette session)

### R1 — URLs canoniques par page
Ajouter `alternates: { canonical: "https://www.odillon.fr/[path]" }` dans les exports `metadata` de chaque page pour prévenir le contenu dupliqué entre `http://`, `odillon.fr` et `www.odillon.fr`.

### R2 — Sitemap dynamique incluant les articles de blog
Étendre `app/sitemap.ts` pour interroger Supabase et inclure les articles publiés :
```typescript
const { data: articles } = await supabase.from("articles").select("slug, updated_at").eq("published", true)
```

### R3 — Métadonnées de la page Photothèque
La page `/phototheque` est un Client Component — créer `app/phototheque/layout.tsx` avec l'export `metadata` pour que Google puisse indexer cette page avec un titre descriptif.

### R4 — JSON-LD Breadcrumb pour les pages Offres
Ajouter des données structurées `BreadcrumbList` sur les sous-pages `/offres/[service]` pour améliorer l'affichage dans les SERP.

### R5 — Conversion Baskvill TTF → WOFF2
La police Baskvill est servie au format TTF. WOFF2 est compressé (30-40% plus léger). Convertir `BASKVILL.ttf` en `BASKVILL.woff2` et mettre à jour `app/fonts.ts` en conséquence.
